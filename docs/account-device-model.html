投递规则

该账号下，扩展当前在线的设备数行为
0 任务保持 WAITING_EXTENSION。所有已登录的客户端提示：「请在一台电脑上安装并打开浏览器扩展」。不让用户挑机器。
1 任务只推到这台。另一台没装扩展，收不到。
≥2 按 extensionBoundAt ASC 取第一台，只 push 给它。其余有扩展的设备也不跑这一单。

「第一台」= 这个账号下第一次上报扩展在线的设备，时间写下 extensionBoundAt，之后不再改。 投递时再滤掉当前不在线的；在线集合里仍然按这个时间取最早。不要用心跳新旧、商家 Cookie、打分。

点做法

      
      
        

          不要按账号广播
          任务 push 到选中的 deviceId。没扩展的客户端连这条通道都没有。
        

        

          taskId 单飞
          Task.assigneeDeviceId 写下第一台。回传带 deviceId；重复上报丢弃。防止两台扩展同时在线时的竞态。
        

        

          第一台离线
          它不在「当前扩展在线」集合里。若还剩别的扩展在线，取集合里 boundAt 最早的（可能变成原来的第二台）。若一个都不在线 → 走 0 台提示。
        

        

          卸扩展 / 重装客户端
          扩展断开则该设备离开候选。重装客户端会得到新 deviceId，extensionBoundAt 是新的，排序上变成「更晚的一台」。
        

        

          商家没登录
          跟调度无关。任务已经打到第一台，由那台回 LOGIN_REQUIRED，引导在这台 Chrome 登录。不要因为 Cookie 再换一台。
        

      
    


    

      约定
      不跑任务 = 不装扩展。调度只认扩展在线列表：0 提示，1 投它，多台投第一台（extensionBoundAt 最早）。
      用户不选执行端。商家登录仍在被选中的那台 Chrome 里完成。
